After Shor · Issue 3

Polynomials on the clock face

18 September 2026·8 min read·Avishek Nag

The ground floor from last issue was Zq, the clock face where all four operations work. But ML-KEM and ML-DSA do not compute in Zq. They compute in Rq = Zq[x]/(x²⁵⁶ + 1): polynomials of degree under 256 whose coefficients are clock-face numbers. Every object downstream has this shape. A ciphertext is a handful of elements of Rq, a signature is built from them, a public key is a matrix of them. This issue derives the three design choices hiding in that one line, and the strange-looking divisor x²⁵⁶ + 1 turns out to be one of the best engineering decisions in the whole standard.

The same move, one level up

Building Rq is the move that built Zq, repeated. There, we fixed an integer q and kept remainders after dividing by it. Here, we fix a polynomial, xⁿ + 1 with n = 256, and keep remainders after dividing by that. Every element of Rq is represented by a unique polynomial of degree less than n, which is to say by its n coefficients, each a number in Zq. Byte for byte, an element of Rq is a fixed-size array of 256 small integers, with no pointers and no variable-length encoding, and the standards’ serialisation formats are exactly “write the coefficients down.”

Addition is coefficientwise and needs nothing further. It is tempting to conclude that Rq is just Zq256 with extra notation, and additively that is true. The ring earns its keep in the multiplication: coordinatewise products would throw away all the algebraic structure, while Rq’s multiplication lets one ring product diffuse information across all 256 coefficients in a single step. The ring structure is not decoration. It is the entire reason the standards use polynomials instead of plain vectors of integers.

Multiplication with a twist

To multiply in Rq, multiply as ordinary polynomials, then reduce. Reduction means substituting xⁿ ≡ −1, because xⁿ + 1 ≡ 0 modulo itself, and that substitution is where the character of the ring comes from. Work the smallest honest example: n = 4, f = 1 + 2x + 3x² + 4x³, multiplied by x. The ordinary product is x + 2x² + 3x³ + 4x⁴, and the last term reduces: 4x⁴ ≡ −4. So

f · x  ≡  −4 + x + 2x² + 3x³   (mod x⁴ + 1)

Multiplying by x rotates the coefficient array one slot and flips the sign of whatever rotates past the top. Run the general case through the same substitution and multiplication in Rq comes out as ordinary cyclic convolution, except that the wrap-around terms come back negated. That minus sign is the whole content of the name this operation carries, negacyclic convolution, and it is the only difference from the convolution used in rings built from xⁿ − 1.

Ten lines of code implement the convolution formula directly, and checking them against rotate-and-negate on random polynomials is the kind of test worth actually running:

def negacyclic(f, g, q):
    n = len(f); h = [0] * n
    for i in range(n):
        for j in range(n):
            k = (i + j) % n
            s = 1 if i + j < n else -1
            h[k] = (h[k] + s * f[i] * g[j]) % q
    return h

print(negacyclic([1, 2, 3, 4], [0, 1, 0, 0], 17))
# [13, 1, 2, 3]   ->  -4 mod 17 is 13: rotate, negate the wrap

Why 256 and not 250

Fixing xⁿ + 1 was a choice, and not every n makes it a good one. The requirement that matters is that xⁿ + 1 should not factor into smaller polynomials, for the same reason last issue wanted a prime modulus: a reducible modulus lets the ring decompose into smaller rings, and a decomposable ring hands an attacker smaller, more structured pieces to work on one at a time.

Suppose n has an odd factor d > 1, say n = dm. For odd d there is a school identity: yᵈ + 1 = (y + 1)(yᵈ⁻¹ − yᵈ⁻² + ⋯ − y + 1), the signs telescoping precisely because d is odd. Substitute y = xᵐ and the identity exhibits xⁿ + 1 as a genuine product of two smaller polynomials. Read the contrapositive: if xⁿ + 1 is to be irreducible, n can have no odd factor above 1, so n must be a power of two. That the power-of-two choice actually delivers irreducibility is a deeper fact about cyclotomic polynomials which we use without reproving, in the same spirit as last issue’s citation that Zq× is cyclic. Both standards take n = 256 = 2⁸: large enough that nothing peels off, small enough that the coefficient arrays stay compact.

One divisibility check decides the rest

Irreducible over the rationals does not mean irreducible over Zq, and what happens over Zq is decided by a single condition on q. Suppose Zq contains an element ψ of order exactly 2n, a primitive 2n-th root of unity in last issue’s language. Then ψⁿ squares to 1 without being 1, and since a prime modulus permits no zero divisors, ψⁿ must be −1. Every odd power of ψ is therefore a root of xⁿ + 1, they are all distinct, and a degree-n polynomial has room for no others: xⁿ + 1 splits completely into n linear factors. Such a ψ exists exactly when 2n divides q − 1, that is, when q ≡ 1 (mod 2n).

The toy case makes it concrete. Take q = 17, n = 4, so 2n = 8 divides q − 1 = 16. Direct search finds ψ = 9, whose odd powers are 9, 15, 8, 2 modulo 17, and brute force confirms that {2, 8, 9, 15} is the complete root set of x⁴ + 1 in Z₁₇. Now the standards’ numbers. Both fix 2n = 512. Last issue factored q − 1 for each: ML-DSA’s 8380416 = 2¹³·3·11·31 is divisible by 512, so its x²⁵⁶ + 1 splits into 256 linear factors. ML-KEM’s 3328 = 2⁸·13 is not, and its polynomial only splits as far as 128 quadratics.

Note what that shortfall is and is not. The convolution formula above is exact for every modulus, so nothing about ML-KEM’s multiplication is broken or approximate. What the divisibility buys is speed: full splitting turns one ring product into n independent products in Zq, while ML-KEM’s transform bottoms out one level early in 128 small 2 × 2 multiplications. Both run fast. Which factorisation the arithmetic exploits is read off one divisibility check before a single coefficient is multiplied.

The security dial is k, not the ring

A single ring element is not enough structure to build a scheme with adjustable security, so both standards work with vectors over Rq. The set Rqk of k-tuples behaves like a vector space with Rq as its scalars, and the operation the standards actually run is a matrix over Rq acting on such a vector, every scalar multiply inside it a negacyclic convolution. Here is the striking design fact: across all six parameter sets of the two standards, n and q never change. ML-KEM at security categories 1, 3 and 5 uses (k, l) of (2, 2), (3, 3) and (4, 4); ML-DSA uses (4, 4), (6, 5) and (8, 7). The ring is chosen once, for the reasons derived above, and the security dial is the integer k, at the cost of a larger matrix and larger keys.

One cost is now sitting in plain view. Computed straight from the convolution formula, a single ring product is n² scalar multiplications, tens of thousands for n = 256, and a matrix-vector product needs kl of them. That cost is large enough to matter and structured enough to fix, and the divisibility condition above is precisely what determines how far it can be driven down. Next issue builds the machine that does it: the number-theoretic transform, which evaluates a polynomial at the powers of ψ the way this issue’s roots suggest, turns convolution into coordinatewise multiplication, and brings n² down to n log n. It is the fast Fourier transform wearing modular clothes, and it is the reason post-quantum key exchange costs microseconds rather than milliseconds.

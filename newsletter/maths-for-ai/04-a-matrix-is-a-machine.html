The Maths Underneath · Issue 4

A matrix is a machine

18 September 2026·6 min read·Avishek Nag

Last issue ended with a promise: the object that holds thousands of vectors at once, and the multiply that runs a neural network. Both are the same thing. A matrix is a table of data, and a matrix is a machine that moves points around space, and switching freely between those two readings is most of what makes model code stop looking mysterious. This issue builds both readings and checks every claim in NumPy.

A stack of vectors

A single song was a vector: two numbers, energy and danceability, fixing one point on a map. A music library is many songs, so stack the vectors on top of each other. Four songs, two numbers each, make a matrix with four rows and two columns:

import numpy as np

M = np.array([
    [0.90, 0.35],   # Thunder
    [0.30, 0.55],   # Sunrise
    [0.75, 0.80],   # Drive
    [0.15, 0.20],   # Lullaby
])

print(M.shape)     # (4, 2)  ->  4 rows (songs), 2 columns (features)
print(M[2])        # [0.75 0.8 ]              -> the song 'Drive'
print(M[:, 0])     # [0.9  0.3  0.75 0.15]    -> every song's energy

One convention is worth fixing now, because most shape bugs trace back to it. In a data matrix, rows are examples and columns are features, always. A dataset of 1,000 images with 784 pixels each is a 1000 × 784 matrix. When a framework reports an input of shape (64, 3, 224, 224), it is saying the same thing with more axes: 64 images, 3 colour channels, 224 by 224 pixels. Reading shapes fluently is a large part of not getting stuck.

Feed it a vector

Here is the second reading, and it is the one that runs deep learning. A matrix takes a vector in and returns a vector out. In that sense it is a machine: a fixed grid of numbers that transforms whatever you feed it.

The rule is mechanical. Each row of the matrix is dotted with the input vector, and each of those dot products becomes one number of the output. Suppose a track has three audio features, energy 0.8, danceability 0.6, acousticness 0.1, and we want two scores out of it: how energetic it sounds and how calm it sounds. Choose a weight matrix with one row per score. The first row rewards energy and danceability and penalises acousticness, which is what energetic should mean:

x = np.array([0.8, 0.6, 0.1])          # energy, danceability, acousticness

W = np.array([[ 0.9, 0.7, -0.8],       # weights for the 'energetic' score
              [-0.5, 0.6,  0.9]])      # weights for the 'calm' score

print(W @ x)   # [1.06 0.05]

Check it by hand, because a sum you did yourself catches shape mistakes early. Row one: (0.9)(0.8) + (0.7)(0.6) + (−0.8)(0.1) = 0.72 + 0.42 − 0.08 = 1.06. Row two: −0.40 + 0.36 + 0.09 = 0.05. The code agrees. The track scores high on energetic and barely registers on calm, which matches a loud, danceable, non-acoustic song.

Now the claim this series has been building toward. A neural network layer is Wx⃗ + b⃗: multiply by a weight matrix, add a bias vector. That is the whole layer. The numbers inside W are exactly what training adjusts, and a model with millions of parameters is millions of numbers sitting in matrices like this small one. Running the model forward is a chain of these multiplies and nothing more exotic, at this level, is going on.

What a matrix does to space

The multiply becomes visual when the matrix is 2 × 2 and the vectors are the plane. Feed a shape through a matrix, point by point, and watch. A diagonal matrix stretches or squashes along the axes, each axis handled separately, like the sliders of a graphic equaliser. A rotation matrix turns everything about the origin by a fixed angle. A shear slides one axis past the other, the way italic type leans upright letters over. Photo software does exactly this when you rotate or skew a picture: one small matrix multiplies the coordinates of every point, and because every point moves by the same rule, the picture stays coherent instead of scattering.

The rotation matrix is worth writing out once, because it appears in graphics, robotics, and signal processing alike. To turn by an angle θ, the matrix has cos θ and sin θ arranged so that east ends up pointing wherever θ says:

theta = np.radians(45)
R = np.array([[np.cos(theta), -np.sin(theta)],
              [np.sin(theta),  np.cos(theta)]])

print(R @ np.array([1, 0]))   # [0.707 0.707] -> east now points north-east

Note that the length did not change: the input had length 1 and so does the output. Rotation moves direction without touching size. Vision models are trained on rotated, scaled, and sheared copies of each image so they recognise an object whichever way it tilts, and those copies are made with matrices exactly like these.

Order is part of the answer

Multiplying two matrices chains two transformations into one, and there is a catch worth respecting. In the product RH, the matrix on the right acts first, so RH means shear with H, then rotate with R. Reading right to left feels backwards, and it matters, because the order changes the result:

H = np.array([[1, 0.6],    # a horizontal shear
              [0, 1  ]])

print(np.allclose(R @ H, H @ R))   # False -> order matters

In ordinary arithmetic 3 × 5 equals 5 × 3. For matrices that guarantee is gone, and it is not a technicality. A deep network is a chain of matrix multiplies applied in a fixed order, one per layer, and deep just means the chain is long. If your output looks scrambled after a refactor, check whether a multiply got reordered before you suspect anything cleverer.

The shape rule polices all of this for you. To compute AB, the columns of A must equal the rows of B: write the sizes side by side, (m × n)(n × p), the inner numbers must match, and the outer ones survive as the size of the result. Our scoring example was (2 × 3)(3 × 1), inner threes match, and out came a 2 × 1 answer. Two scores, as promised.

Next issue runs the machine backwards. You are handed the output and the matrix, and you must recover the input: two shoppers, two receipts, and the unknown prices of an apple and an orange. That one puzzle leads to when a solution exists at all, to how much information a matrix really holds, and to the best possible answer when no exact one exists, which is a line fitted to noisy points and the simplest model in all of machine learning.

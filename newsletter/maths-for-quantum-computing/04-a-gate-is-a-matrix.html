Amplitudes · Issue 4

A gate is a matrix

2 October 2026·7 min read·Avishek Nag

Last issue built the nouns: a qubit state is a unit column of two complex numbers, and you can now write any of them down. What you cannot yet do is change one state into another. The object that does it is a matrix, and the claim of this issue is stronger than it sounds. A quantum gate is not described by a matrix, or modelled by one, or conveniently represented by one. A gate is a matrix, and running a circuit is nothing but multiplication. Everything in this issue runs in NumPy, and every product is small enough to check with a pencil first.

A table and a rule

A 2 × 2 matrix holds four numbers in two rows and two columns. Read as a table, that is all it is. Read as a transformation, the same four numbers are a rule that takes any vector in and returns a vector out. Take A = [[2, 0], [0, 1]]: the rule is “double the first coordinate, leave the second alone.” Feed it the unit square, corner by corner, and the square comes out a rectangle twice as wide. The columns of a matrix are exactly where the two basis arrows land, (1, 0) on column one and (0, 1) on column two, so you can read a matrix’s whole effect straight off its columns. This works because the rule is linear, it respects adding and scaling, and the correspondence is exact: every linear map is a matrix, every matrix is a linear map. The whole of this issue rests on that one fact.

Rows times columns

The core operation is a matrix times a vector, and the rule is mechanical: each row of the matrix is dotted with the vector, and each dot product becomes one entry of the output. Work one through. A = [[2, 0], [0, 1]] on v = (3, 4): first row gives 2·3 + 0·4 = 6, second row gives 0·3 + 1·4 = 4, so Av = (6, 4), the doubling rule as promised. Now a matrix that mixes the coordinates, B = [[0, 1], [1, 0]], on the same v: first row 0·3 + 1·4 = 4, second row 1·3 + 0·4 = 3. So Bv = (4, 3). This B swaps the two coordinates, and remember it, because it is about to get a famous name.

import numpy as np
np.set_printoptions(precision=3, suppress=True)

A = np.array([[2, 0], [0, 1]])
B = np.array([[0, 1], [1, 0]])
v = np.array([3, 4])

print(A @ v)   # [6 4]
print(B @ v)   # [4 3] -> the coordinates are swapped

One warning before the physics, because it is the single most common bug in beginner quantum code. In NumPy, @ is matrix multiplication and * is elementwise multiplication, and they are different operations that share the word multiply. M * M squares each entry where M @ M is the true product, and writing X * ket where you meant X @ ket runs silently and returns a wrong array of the right shape. The error message never says “you meant @”, because there is no error message.

The NOT gate is a swap

Now apply the swap matrix to last issue’s basis states, |0⟩ = (1, 0) and |1⟩ = (0, 1). By the row rule, B·|0⟩ = (0, 1) = |1⟩, and B·|1⟩ = (1, 0) = |0⟩. The matrix flips 0 to 1 and 1 to 0, which is why it is called the NOT gate and written X. The second gate worth meeting today is the Hadamard, H, which is 1/√2 times [[1, 1], [1, −1]]. Feed it |0⟩ and out comes (1/√2, 1/√2), which is exactly the equal superposition |+⟩ from issue 3, both amplitudes 1/√2, both measurement probabilities ½. The gate that creates superposition is a small real matrix, and watching it act is one line:

ket0 = np.array([1, 0], dtype=complex)
ket1 = np.array([0, 1], dtype=complex)

X = np.array([[0, 1], [1, 0]], dtype=complex)
H = np.array([[1, 1], [1, -1]], dtype=complex) / np.sqrt(2)

print(X @ ket0)   # [0.+0.j 1.+0.j] == |1>
print(H @ ket0)   # [0.707+0.j 0.707+0.j] == |+>
print(np.allclose(H @ H @ ket0, ket0))   # True -> H undoes itself

Note the dtype=complex, even though every entry here is real. Gate entries are complex in general, the Y gate carries ±i, and a real-typed array would silently discard the imaginary parts the moment they appear.

Order is part of the circuit

Multiplying two matrices builds the single matrix that does both transformations in sequence, and the order reads right to left: in the product AB, it is B that acts first, because B sits next to the vector. There is a catch, and it is not a technicality. Take A = [[1, 2], [0, 1]] and B = [[1, 0], [3, 1]] and work all four dot products each way: AB comes out [[7, 2], [3, 1]] while BA comes out [[1, 2], [3, 7]]. The two products differ, and that is the normal situation, not a quirk of these numbers. In ordinary arithmetic 3 × 5 equals 5 × 3; for matrices that guarantee is gone. A circuit that applies X, then H, then X is the single matrix XHX, and reordering the gates generally computes something else. When a simulator runs your circuit, it is doing exactly this: either multiplying the gate matrices into one and applying it, or applying them to the state one at a time. Both give the same answer, which is why it is free to pick whichever is cheaper.

The one property every gate must have

Not every matrix gets to be a gate, and the test was promised last issue. A state’s squared amplitudes are measurement probabilities, so they must sum to 1, which is the statement that the state is a unit vector. A legal gate must therefore map unit vectors to unit vectors: it may rotate and reflect, never stretch. The matrices that preserve length have a name and a one-line test. Write U† for the conjugate transpose of U, the dagger: transpose the matrix, then conjugate every entry. A matrix is unitary when U†U = I, and unitary is precisely the length-preserving condition. It also hands you the undo button for free: U†U = I says U† is the inverse of U, so every gate can be run backwards by taking its dagger, with no matrix inversion in sight. Quantum gates are reversible by construction, which is a real constraint on hardware and a real difference from a classical AND gate, which destroys a bit of input and cannot be run backwards.

def is_unitary(U):
    return np.allclose(U.conj().T @ U, np.eye(U.shape[0]))

Y = np.array([[0, -1j], [1j, 0]])
print(is_unitary(X), is_unitary(H), is_unitary(Y))   # True True True

v = np.array([0.6, 0.8])                   # a unit vector: 0.36 + 0.64 = 1
print(round(np.linalg.norm(H @ v), 12))    # 1.0 -> the length survived

Two cautions close the loop. First, write the dagger as .conj().T, always: for real matrices the plain transpose happens to agree, so the missing conjugate hides until a complex entry arrives, and then it is wrong. Second, invertible is not enough. The stretching matrix [[2, 0], [0, 1]] from the top of this issue has a perfectly good inverse and is still not a legal gate, because it turns a unit vector into one of length greater than 1, which would make probabilities sum past certainty. Unitarity is the whole entry requirement: it is what conserves total probability, and it is what makes every quantum computation, before measurement, a reversible rotation of a very large space.

You can now apply a gate to a state and chain gates into circuits, which is most of the mechanics of a quantum program. What is still missing is how to compare two states: how to ask how much one overlaps another, and where the measurement probabilities really come from. That question is an inner product, and it is where the bra ⟨ψ| finally joins the ket. Next issue builds it, shows why the inner product of a state with itself is the normalisation rule we have been checking all along, and meets the number ⟨φ|ψ⟩ whose squared magnitude is the chance that a measurement finds one state as the other.

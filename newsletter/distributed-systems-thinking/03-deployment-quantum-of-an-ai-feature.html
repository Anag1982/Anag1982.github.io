The Expensive Answers · Issue 3

What is the deployment quantum of an AI feature?

4 September 2026·4 min read·Avishek Nag

A team I know shipped a two-service architecture and celebrated on Tuesday. On Friday, a routine schema migration on one service took the other one down for eleven minutes. The post-mortem was one sentence long: we have two services and one system.

The honest number

The diagram said two. The outage said one. Both services read the same database, and a shared schema is a shared contract: a migration deploys everyone’s world, whatever the boxes on the whiteboard claim. There is a name for the honest number, and it comes from Richards and Ford: the architecture quantum, the smallest unit you can deploy independently, together with everything it cannot be deployed without. Boxes on a diagram are free. Independence is bought, separately, and most teams have less of it than they think. Six microservices sharing one database is one quantum. Six microservices behind a frontend that deploys as a single artifact is one quantum again. The counting takes five minutes and regularly ruins a good diagram.

That much is classical. Here is where it gets interesting for anyone shipping AI features.

The four artifacts that move together

Ask the quantum’s founding question, what must move together, about a production AI feature, and four artifacts answer that no deployment tool treats as one thing: the model version behind your vendor’s API, the prompt templates tuned against that model, the embedding-index version your retrieval runs on, and the evaluation set that defines what a good answer looks like.

Watch what happens when one moves alone. The vendor upgrades the model on its own schedule: prompts tuned for the old model’s habits quietly degrade, and your evaluation thresholds, calibrated against the old behaviour, now report either false alarm or false comfort. Someone improves a prompt: outputs shift, and last month’s evaluation scores no longer describe the system that is running. The embedding model gets upgraded and the index rebuilt: retrieval hands different passages to the same prompts, and generation composes answers from different raw material. In every case, the change was deployed to one artifact and the behaviour change arrived through all four.

That is static coupling in every sense that matters. Nobody drew it, because the four artifacts live in four different tools: an API console, a Git repository, an index store, and, if we are honest, a spreadsheet.

The rule, and the four habits that follow

So here is the rule I now teach, and as far as I know the framing is my own: the deployment quantum of an AI feature is the tuple of model version, prompt set, index version, and evaluation set, and it should be versioned, released, and rolled back as one unit.

In practice, four habits follow. Give the tuple a version number of its own. Release it through one pipeline, whatever the artifacts’ home tools are. Canary it as a unit, because a canary that varies one element while three drift in the background is not a canary, it is a coincidence. And roll it back as a unit, because reverting the prompt against the new model is a configuration that never existed and was never tested.

Teams that skip this discover the coupling the way the two-service team discovered theirs, except worse, because nothing errors. The system keeps answering. The answers just get quietly worse, for weeks, until someone notices a metric that nobody owns has been sliding. Discovering the tuple in advance costs a version number. Discovering it in production costs a fortnight of debugging a system in which nothing failed.

One caveat, in fairness. A quantum count of one is not a defect, in classical systems or here. The two-service team kept their shared database, deliberately, with the reasoning written down, because at their scale it was the right debt. The point is never that more independence is better. The point is to know what you actually have, so the diagram stops doing the lying.

A question worth putting to your own team, because the answer is usually instructive: which of the four artifacts has moved alone, and what did it cost to notice?

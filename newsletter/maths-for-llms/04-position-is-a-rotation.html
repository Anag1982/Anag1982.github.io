Attention, Derived · Issue 4

Position is a rotation

2 October 2026·8 min read·Avishek Nag

Last issue’s derivation quietly used a fact it never faced: attention treats its input as an unordered set. Nothing in the score knows that dog bites man differs from man bites dog, so order has to be put in by hand. This issue makes the blindness precise, shows why the first fix fails, and then does what this series is for: instead of presenting the modern injection as a trick, it asks for what is wanted, writes that want as an equation, and watches the equation force its own answer. The answer is strange and lovely. Position is a rotation.

Attention is blind to order

The claim can be made exact. Shuffle the rows of the input with a permutation matrix P and chase it through attention: the projections pick up P, the logit matrix becomes PSPᵀ, a row-wise softmax commutes with permuting rows and columns together, and the final PᵀP collapses to the identity. What is left is Attn(PX) = P·Attn(X): shuffle the input and the output shuffles identically, with nothing in the computation noticing. One rider matters in practice. The causal mask of a decoder is not permutation-invariant, so a decoder trained with no positional encoding at all does learn usable word order from the mask alone: how many tokens a query can see is itself a position signal. What the mask supplies is an ordering, not a metric. It distinguishes before from after, and it cannot distinguish three tokens back from three thousand, which is why every model that must reason about long documents encodes position explicitly.

Why adding position fails

The first answer, the one most readers meet first, adds a fixed sinusoidal vector to each token before the projections, with a different frequency per coordinate pair. The construction has a seductive property, a shift in position is a linear map on the encoding, and the original paper offered it as a reason to expect extrapolation to longer sequences. The expectation was not met, and expanding one logit shows why. With position added to content, the product (x + PEm)WQWKT(y + PEn)T opens into four terms: a pure content term, a term coupling the query’s absolute position to the key’s content, the mirror of that, and only one term involving both positions together. Nothing constrains the learned projection matrices to preserve the structure that made the encoding attractive, and two of the four terms are not relative quantities at all. Learned absolute embeddings, a lookup table indexed by position, share the problem and add a harder one: there is no row for position 8193 if the table stops at 8192.

The fix is to stop adding position to the token and start applying it to the query and key directly, inside the inner product, where relative structure can be made to survive.

Ask for what you want

So ask. We want a map f(x, m) that applies position m to a vector x such that the attention logit depends on positions only through their difference: ⟨f(q, m), f(k, n)⟩ = g(q, k, n − m), with f(x, 0) = x. That is a functional equation, and restricting f to be linear in x, so f(x, m) = xAₘ for some matrix Aₘ, it essentially solves itself in four moves. The condition says AₘᵀAₙ depends only on n − m; call it G(n − m). Setting m = 0 gives G(n) = Aₙ. Setting n = m gives AₘᵀAₘ = I, which is worth pausing on: orthogonality is not assumed anywhere, it is forced, and it is exactly the property that keeps ‖f(q, m)‖ independent of position, so no absolute-position magnitude term can leak into the logit. The two facts together make m ↦ Aₘ a one-parameter group, Aₘ = exp(mΘ) with Θ skew-symmetric, and a real skew-symmetric matrix block-diagonalises into 2 × 2 rotation blocks. The general solution of the equation is: pair up the coordinates, and rotate pair i by the angle mθᵢ. That is RoPE, the rotary position embedding, and the pairing of adjacent coordinates is a convention chosen because it makes the rotation cost a handful of multiplies instead of a matrix product.

The identity that makes it useful follows from angle addition, block by block: RₘᵀRₙ = Rₙ₋ₘ, and therefore ⟨Rₘq, Rₙk⟩ = qᵀRₙ₋ₘk. Only the difference of positions survives the inner product, exactly, at every length. Ten lines check it numerically, and the assertion is the kind worth actually running:

import numpy as np

def rot(x, pos, theta):                  # rotate each pair i by pos * theta[i]
    out = x.copy().reshape(-1, 2)
    c, s = np.cos(pos * theta), np.sin(pos * theta)
    out = np.stack([c * out[:, 0] - s * out[:, 1],
                    s * out[:, 0] + c * out[:, 1]], axis=1)
    return out.reshape(-1)

rng = np.random.default_rng(0)
theta = 500_000.0 ** (-2 * np.arange(4) / 8)     # the frequency ladder, d_h = 8
q, k = rng.normal(size=8), rng.normal(size=8)

lhs = rot(q, 57, theta) @ rot(k, 1234, theta)    # positions 57 and 1234
rhs = q @ rot(k, 1234 - 57, theta)               # only the gap of 1177
print(np.allclose(lhs, rhs))                     # True -> relative, exactly

The ladder of wavelengths

The frequencies θi = b−2i/d form a geometric ladder, and the useful way to read them is as wavelengths, λi = 2πb2i/d: the number of tokens pair i needs to complete one full turn. Take a representative 2026 configuration, head dimension 128, so 64 pairs, and base b = 500,000. The fastest pair turns once every 6.28 tokens. The slowest turns once every 2.56 million. That range is the whole point, and it is also the problem. A pair whose wavelength exceeds the trained context never completes a rotation while the model is learning: it has seen phases only in a small arc, and it has no experience of anything outside that arc. The boundary is a number you can compute from the config file alone: the first pair with λi larger than the trained context. At a trained context of 8,192 tokens, λ₃₄ ≈ 6,695 still fits and λ₃₅ ≈ 8,219 does not, so the boundary sits at pair 35. Pairs 0 to 34 were exercised through complete cycles. The other 29, nearly half the ladder, never once saw a full turn.

The ladder also explains a change that looks like tuning and is not. Early RoPE models used base 10,000, whose wavelength ceiling is 2π × 10,000, about 63,000 tokens. At that base, no pair has a wavelength long enough to tell positions 131,072 apart without wrapping; the encoding cannot represent the distance at all, whatever the training. Raising the base to 500,000 lifts the ceiling to 3.14 million. It is a precondition for long context rather than an optimisation of it, and it has a price: at the higher base, fewer pairs complete a turn during training, which is exactly the 29 above.

What “relative” does not buy

A claim you will meet everywhere: RoPE is relative, so a RoPE model generalises to longer contexts for free. The algebra generalises; the model does not. The identity ⟨Rₘq, Rₙk⟩ = qᵀRₙ₋ₘk held in the code above with no assumption about m or n being small. What fails is that the learned function is defined on the phases it has actually seen, and 29 of 64 pairs present out-of-distribution phases the moment the context stretches. The failure is in the weights, not the encoding, the same category error as expecting a polynomial fitted on [0, 1] to behave at x = 16 because the polynomial is defined there. The symptom is a cliff, not a slope: perplexity flat out to roughly the trained length, then up by orders of magnitude within a few hundred tokens. Adding parameters will not move it. The extension methods in production are three policies over the one diagnostic this section computed: position interpolation slows every pair alike, correct at the top of the ladder and destructive at the bottom; NTK-aware scaling raises the base so slow pairs stretch most; and YaRN makes the non-uniformity explicit, leaving well-exercised bands alone and interpolating in proportion to how little each band rotated, with the ramp’s lower edge landing precisely on the never-completed-a-turn test.

Note what became of the teaser question. Why rotation, of all things? Because the demand “logits may depend only on relative position, and position zero changes nothing” admits essentially one linear solution, and it is the orthogonal, angle-adding, norm-preserving family of rotations. Meet any new positional scheme and the first question to ask is which clause of that demand it gives up.

Next issue steps between the blocks, to the operation this series has so far taken on faith: normalisation. Why every token’s vector is projected back onto a sphere before each block, why modern models dropped the mean-subtraction half of the original recipe and kept the radial half, and what the residual stream that everything reads from and writes to really is.
